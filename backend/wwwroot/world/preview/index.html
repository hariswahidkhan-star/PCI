Why a tour, not the product

Launch is a decision, not a deployment

Each of these surfaces sits behind a feature switch that ships off, and the ones that touch people hardest refuse to run until a prerequisite is recorded: a contracted moderation provider for the rooms, an applicant privacy notice for careers, contributor terms for publishing. That refusal lives in the endpoint, not the interface — so these pages can show you everything while the deployed routes honestly answer 404. When the decisions land, an operator turns each surface on from the launch board. Nothing here requires a redeploy.

How to read this tour

A

The amber registers are real

Every screen opens with the rules the real server enforces. Those sentences are quoted from the system, not invented for the page — the drawing cannot enforce them, the endpoints do.

B

Nothing here is wired

These are plain static pages: no API calls, no database, no feature flag. Buttons answer with the words the product uses, and nothing you type is stored, sent or checked.

C

The endpoints already exist

Each screen lists the API calls it needs under “What this screen calls”. Almost all of them are built and tested today — the tour is the map for whoever wires the last mile.
