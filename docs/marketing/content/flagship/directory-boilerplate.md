# PCI directory and profile boilerplate

Eight lengths of one description, an entity block, a category ladder and a keyword list. Fill every
listing from this file and nothing else. If a field needs text that is not here, it needs approval,
not improvisation.

The rule that governs the whole set: **paste the largest version that fits the field, and never pad
to fill it.**

## The entity block — the fields that never change

Identical in every listing. A directory profile is worth having because it corroborates an entity,
and it corroborates nothing if the details drift.

| Field | Value |
|---|---|
| Display name | Project Controls Institute Global |
| Short name, where a field is tight | Project Controls Institute |
| Abbreviation | PCI, and only after the full name has appeared in the same field |
| Website | https://projectcontrolsinstitute.org — no trailing path, no UTM, no variation |
| Credential names, in full | PCI AI Project Controls Leader (PCL-AI) · PCI AI Project Finance Leader (PFL-AI) · PCI Project Management Leader – AI (PML-AI) |
| Name, address, telephone | Exactly as on the hub's About page and Google Business Profile, to the punctuation |

**Never written, in any field, on any platform:** PCI Global · The Project Controls Institute ·
Project Control Institute · Project Controls Institute International · PCI Institute · PCL AI or
PCL/AI · Project Controls Leader AI without the PCI prefix · PCP-AI, which is the superseded code
and must never reappear in a profile. Each of these splits the entity, and a wrong name in a
directory costs more to unpick later than it saves now.

**Fields with no approved answer.** Founded year, headcount, revenue, funding, awards, accreditations,
students certified, pass rates. Leave every one of them blank unless the person filling the form is
reading it off a record. An estimate in a Crunchbase field is a published statistic the moment it is
saved, and it will be quoted back.

## Categories — the ladder, in order of preference

Choose the highest option the platform actually offers. The category tells the platform what PCI
sells, and it is harder to change than the description.

1. Certification body · certifying organisation · standards body
2. Professional association · professional body · membership organisation
3. Education · educational institution · professional training
4. E-learning, only where the list offers nothing above it

**Never choose:** accreditation body (a different thing, and a claim PCI cannot make) · accredited
training provider · software · SaaS · consulting · recruitment or staffing · accountancy practice ·
exam preparation.

| Platform | Category to select |
|---|---|
| Google Business Profile | The nearest available of certification agency, educational institution, association. Do not pick a training-centre category if a certification one exists |
| Crunchbase | Education and the nearest of professional training or certification. Do not tick software or SaaS |
| LinkedIn Page | Professional training and coaching, or education, whichever the industry list offers; company type: educational institution or non-profit as the registration actually stands |
| Credly | Issuer profile, described as a certifying body |
| F6S, Tracxn | Education or EdTech, with certification named in the description rather than the tag |

**Two rules the table depends on.**

**Never truncate a longer version to fit.** The instruction at the top of this file is to paste the
largest version that fits and not pad it; the mirror of that is not cutting a longer one off at the
character limit. A truncated description ends mid-claim, and the claim it ends mid-way through is
usually the one about what PCI does not hold. Where a live field is tighter than the row says, drop
to the next version down. That is what the ladder is for.

**Registries and catalogues stop before the last sentence.** The 250-word and 100-word versions end
on an invitation to the reader — read the domains against your own last month-end. That is right on
a Crunchbase or LinkedIn profile and wrong in Credential Registry or any formal catalogue record,
where an imperative to the reader marks the entry as promotional to exactly the librarians and
indexers who make the record worth having. Removing the final sentence is the only approved edit to
any version in this file. Nothing may be added in its place.

Where a directory writes its own summary by scraping, the defence is that every source it can reach
says the same 160 characters. That is the whole argument for consistency over freshness here.

## Review platforms are a different decision

Trustpilot, G2 and Capterra collect reviews from customers about a product. They are not description
fields with a review section attached, and putting PCI on one before there is something to review is
how a profile ends up with two ratings and a permanent average.

- **Trustpilot.** Open a profile only when candidates have completed something they can honestly
  review. Never seed a review, never write one internally, never offer anything in exchange for one,
  and never review-gate by asking happy candidates only. All four breach the platform's rules and
  the first is the one that ends a certifying body.
- **G2 and Capterra.** Software directories. The only thing PCI could list there is the assessment
  platform as software, and if there is no product a buyer purchases as software, do not create the
  listing. A credential described as a software product invites a feature comparison it will lose
  and a category it does not belong in.
- **Any platform.** A one-star review is answered in public, once, in the same voice as the 250-word
  version: what PCI examines, what it does not claim, and an offer to take the detail off the thread.
  No arguing, no legal language, no deletion requests.

## After a profile goes live

Two jobs, both small and both usually skipped.

1. **Add the profile URL to the `sameAs` array** in the Organization schema on all five domains. The
   array lists verifiable third-party profiles, which is the legitimate instrument for associating
   the domains with one organisation, and it does properly the job the reciprocal link block is a
   poor substitute for.
2. **Record the login, the field limits you actually hit, and the date** in whatever the team uses.
   The second person to edit a listing is always someone else, and half the corrections in this
   category are caused by a profile nobody can get back into.

**Wikidata.** Do not create an item for the Institute. Wikidata items follow independent coverage;
a self-created one is proposed for deletion and the deletion is itself a public record. It comes
after the trade press, not before it.
