# Cut-Off Error in Earned Value Reporting: A Closed-Form Result for the Cost Performance Index, the Forecast at Completion and Recognised Revenue

**[AUTHOR NAME]**
[Role], Project Controls Institute Global
[City, Country] · [EMAIL]

**Working paper. Version 1.0. Date written: [DATE].**

## Abstract

A cost performance index is read as a statement about productivity. It is also a statement about which ledger was open on which date. This paper formalises the cut-off differential: the interval between the close of a project's cost ledger and the date its progress is measured, together with work performed inside it and not yet invoiced. Where posted cost stands in for incurred cost, the reported index is overstated by exactly one plus the accrual ratio, the accrual as a proportion of posted cost. Earned value cancels from the expression, so the overstatement is invariant to the rules of credit and does not fall as progress measurement improves. In the demonstration the index reads 1.19 on posted cost and 1.05 on incurred cost. Three propagations follow. A forecast at completion taken from the index is understated by the reciprocal of the same factor, whatever the budget. Where progress is measured for revenue by a cost-to-cost input method, the same omission understates recognised revenue, so the cost report is flattered and the revenue figure conservative in one period from one cause. Where the accrual ratio varies between periods, the reported series carries a multiplicative component set by accrual practice rather than by work, which passes into trend analysis and into comparison between projects. Neither schedule index contains a cost term, and a detector estimated on posted transactions has no positive class for a transaction that was never posted. The exposure is structural, and neither professional syllabus examines the handover.

**Keywords:** earned value management; cut-off; accruals; cost performance index; estimate at completion; forecast at completion; revenue recognition; input methods; percentage of completion; project controls; management reporting; anomaly detection; professional certification

**JEL Classification:** M41, M11, O22, L74, G31, M53

## Outline of the paper

**1. Introduction.** Accountancy examinations rarely test float. Engineering examinations rarely test cut-off. A project requires both every month, and it requires them of the same number. The section states the substitution the paper is about, that posted cost stands in for incurred cost inside the reporting pipeline, and sets out the five results.

**2. Definitions and notation.** A project closes three times a month and calls it one close: the ledger close set by the finance calendar, the data date set by project controls, and the valuation date set by the contract. The cut-off differential is defined as the interval between the first two, together with the work performed inside it and not yet invoiced. The accrual ratio *r* is the accrual over posted cost.

**3. How the substitution arises.** The substitution is rarely deliberate and almost never written down. The invoice is the artefact both functions can see, and the quantity both functions can see is the quantity that reaches the report. The section argues that this is an interface failure rather than an error in either system, since each has closed to the date it is required to close to.

**4. A demonstration.** Earned value 2,200,000 against invoiced cost 1,850,000 gives 2,200,000 ÷ 1,850,000 = 1.19. With 240,000 of work performed and not yet invoiced accrued, 1,850,000 + 240,000 = 2,090,000 and 2,200,000 ÷ 2,090,000 = 1.05. The figures are illustrative arithmetic carrying no currency, sector or client, and no frequency is claimed for them.

**5. The general result, and why better measurement does not help.** Reported index over true index equals (*C*p + *A*) ÷ *C*p = 1 + *r*. Earned value cancels from the expression: the overstatement is invariant to the rules of credit, so no improvement in progress measurement reduces it by a single point. In the demonstration 240,000 ÷ 1,850,000 = 0.1297, an overstatement of 12.97 per cent, which is the distance between the two indices before either is rounded for reporting.

**6. Propagation into the forecast and into revenue.** A forecast at completion computed as budget over the index inherits the reciprocal, so the corrected forecast exceeds the reported one by 1 + *r* = 2,090,000 ÷ 1,850,000 = 1.13, and the size of the error is knowable without knowing the budget. Where progress is measured for revenue by a cost-to-cost input method, the same omission understates the numerator and so understates recognised revenue. The section carries the caveat that where total expected cost was itself built from the same posted-cost run rate, part of the effect cancels by an amount that cannot be established without inspecting how the estimate was made.

**7. Series and portfolio effects.** Where the accrual ratio varies between periods, the reported index for a period equals the true index multiplied by one plus that period's own accrual ratio, so the reported series carries a component driven by accrual practice and not by work. Two projects of identical productivity and differing accrual discipline report different indices, which means a portfolio ranking built on reported indices is not a ranking on a common basis. The section notes that the correction, when it is finally posted, arrives in the following period as an adverse cost variance with no operational cause.

**8. Observability.** Schedule variance and the schedule performance index are computed from earned value and planned value and contain no cost term, so a cut-off error is invisible to both and schedule review will not surface it. The section derives the diagnostic that follows: a period in which the cost index moves materially while the schedule index is stationary, with no operational change recorded, is a question about cut-off before it is a question about productivity, and the same test applies in reverse to an improvement nobody challenged.

**9. Why automated review does not close the gap.** Precision and recall are estimated over a labelled population of observed records. A detector trained on posted transactions has no positive class for a transaction that was never posted, so its recall over unrecorded events is not low but undefined. The governance question is therefore not whether the tool computes correctly but which figures a model may originate, which it may only restate from a tested source, and whose name stands on the output. ISO/IEC 42001 and the NIST AI Risk Management Framework both put that question to any organisation deploying such a system without prescribing the answer for a project record; the section sets out what a written answer has to settle, and [one published policy of that kind](https://pciai.org/ai-policy-for-project-controls) is cited as an example of the form, not as a recommendation.

**10. The examination boundary.** A tabulated comparison of where each object is examined, produced and consumed: cut-off and revenue recognition in accountancy syllabuses, float and logic in engineering and project management syllabuses, and the forecast at completion produced under one syllabus and consumed unaltered under the other into a statement that will be audited. The claim is structural and not a claim about competence. Each boundary was drawn for good reasons; what is not defensible is that the interface between two well-drawn boundaries is examined by nobody, while a named individual signs the number that crosses it.

**11. Limitations.** The paper offers a derivation and not an estimate. It establishes what follows when posted cost is substituted for incurred cost; it does not establish how often the substitution occurs, in what sectors, or at what magnitude, and no such frequency is claimed anywhere in it because the author has no sample that would support one. The arithmetic is illustrative. Nothing in the paper is legal, tax or accounting advice.

**12. Declaration of interest, and what is not claimed.** The author is affiliated with the Project Controls Institute, which certifies against three credentials built for this interface: the PCI AI Project Controls Leader (PCL-AI), examining 13 domains and 61 knowledge areas; the PCI AI Project Finance Leader (PFL-AI), examining 16 domains and 61 knowledge areas; and the PCI Project Management Leader – AI (PML-AI), examining 16 domains and 63 knowledge areas. They rest on 113 mandatory PCI Standards carrying 532 process requirements, which are certification requirements established by the Institute and are not law. The Bodies of Knowledge are built in proportions of 40 per cent finance and reporting, 40 per cent project management and 20 per cent governed use of machine output; that describes the Body of Knowledge and not the examination, no examination weighting is published, and a weighting attributed to a PCI examination did not come from the Institute. Of those materials, 15,613 machine calculation checks run against PFL-AI and PML-AI, all passing, and PCL-AI has no equivalent suite; those checks cover the Institute's own worked material and not the derivations in this paper, which stand or fall on the algebra in Sections 5 to 7. What is not claimed: no accreditation, recognition, endorsement, affiliation or partnership, none of which has occurred; no pass rate, no student numbers, no salary effect and no guaranteed outcome; and no suggestion that any of this substitutes for a statutory or chartered qualification where the work requires one. [The syllabus that examines this interface](https://projectcontrolsinstitute.org/body-of-knowledge) is published in full, so a reader who would rather test the boundary than the argument has the text to test it against.

**Appendix A. A replication protocol on one reporting period.** Four steps, performed on the reader's own last close. Identify whether the cost figure in the denominator of the reported index is posted cost or incurred cost, which in many pipelines cannot be answered from the report and must be traced to the extract. Divide the accrual raised at the same date by posted cost, which gives the overstatement directly. Compare the ledger close date with the data date, the interval being the population the accrual should have been drawn from. Establish whether the cost basis in the index is the basis used to measure progress for revenue; where it is not, the two reports disagreed all month and neither said so.
