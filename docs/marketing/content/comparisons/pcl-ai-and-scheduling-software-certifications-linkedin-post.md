# The tool did what you told it. The number is wrong.

*LinkedIn text post — 1,836 characters including hashtags. No link in the body; the link goes in the first comment.*

Three fields in a planning package are called per cent complete.
Only one of them should ever earn value, and nobody typed a wrong number the month the forecast moved £1.17m.

Worked case. Control account budget £4.0m. The activity runs 100 days and 60 days have elapsed, so the duration measure reads 60%. On site, 4,500m of 10,000m is installed, so physical progress is 45%. Actual cost to date is £2.10m.

Earn on duration: EV = 0.60 × 4.0 = £2.40m. CPI = 2.40 ÷ 2.10 = 1.14.
Earn on units installed: EV = 0.45 × 4.0 = £1.80m. CPI = 1.80 ÷ 2.10 = 0.86.

EAC = BAC ÷ CPI gives **£3.50m** against **£4.67m**. Same file, same cut-off, £1.17m apart.

The software was right both times. It earned against the field it was told to earn against.

Product certifications for scheduling software examine operating the product, and they examine it properly: data structures, calendars, constraints, resource loading, baselines, layouts, reporting. That is a real skill and it is the thing an employer needs on Monday.

Which field ought to earn is a different subject. It is a rules-of-credit decision, settled before anyone opens the software, evidenced at measurement and defended at month end against a ledger that closed on its own date.

If the advert names the package and you cannot drive it, do the product certification first. Nothing here substitutes for that.
