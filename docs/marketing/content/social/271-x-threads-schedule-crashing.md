# Crashing a schedule without buying the same day twice

*X / Threads thread — 6 posts, each under 280 characters and each able to stand alone. The link sits in the final post. Character counts are for production; X counts any URL as 23 characters, so the live figures run lower.*

**Post 1/6 — the hook** (182 characters)
We crashed the critical activity by six days. The finish date moved five.

That is not an error in the maths. The sixth day was sitting on a different path, and nobody had priced it.

**Post 2/6 — the network** (215 characters)
Worked case. Two paths into the same milestone.

Path 1: A 12d → B 20d → C 8d = 40 days.
Path 2: A 12d → X 15d → C 8d = 35 days.

B is on the critical path. X carries 5 days of total float and no one is watching it.

**Post 3/6 — the arithmetic** (213 characters)
Crash cost on B: 20d down to 14d for £48,000. Cost slope = £8,000 a day.

Buy all six days: path 1 = 34 days. Path 2 is still 35, so the finish is 35.

Six bought, five gained. £48,000 ÷ 5 = £9,600 per useful day.

**Post 4/6 — the sixth day costs double** (243 characters)
Past day five both paths are critical, so day six must be bought on both. B costs £8,000 and X has a slope of £6,000, so that day costs £14,000.

Liquidated damages are £25,000 a day, so it still pays. Buy it knowingly rather than by accident.

**Post 5/6 — where crashing fails** (266 characters)
Crashing works only on the binding path, and only where the work divides. A second crew halves a cable pull. It does not halve a 28-day concrete cure and it does not halve an inspection one authority performs once.

Re-run CPM after every step. The constraint moves.

**Post 6/6 — the rule** (302 characters)
Rank candidates by cost per useful day, crash one step, re-run the network, repeat. Stop when the next day costs more than the delay it prevents. Fast-tracking is the other lever and it pays in risk instead of cash.
