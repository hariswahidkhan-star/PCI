# The overlap where projects lose money: one worked month

*X / Threads thread — 7 posts, each under 280 characters and each able to stand alone. The link sits in the final post. Character counts are for production; X counts any URL as 23 characters, so the live figures run lower.*

**Post 1/7 — the hook** (179 characters)
The cost report moved £4.9m. The month-end result moved £3.54m, all of it in one month.

The cost engineer thought he had flagged a forecast. He had triggered an onerous contract.

**Post 2/7 — the numbers** (215 characters)
Worked case. Fixed price £42.0m. Expected cost at last month-end £38.6m, so margin £3.4m. The cost-to-cost measure had the job at 60% complete.

This month the cost engineer's estimate at completion lands at £43.5m.

**Post 3/7 — the arithmetic** (199 characters)
What finance runs on that number:

Expected loss = 43.5 − 42.0 = £1.5m, recognised in full now.
Margin taken to date = 0.60 × 3.4 = £2.04m, reversed.
Hit to this month's result = 2.04 + 1.5 = £3.54m.

**Post 4/7 — why delivery missed it** (228 characters)
In a cost report an estimate at completion is a forecast that can move again next month. In the ledger it is a trigger. The test is whether a loss is expected, not whether it is certain, and it is taken when it becomes expected.

**Post 5/7 — why finance missed it** (236 characters)
It runs the other way too. An accountant reading £43.5m cannot tell whether it is a rate that repeats or a one-off remediation that does not. Cause lives in the cost tool. Recognition lives in the ledger. They meet on day four of close.

**Post 6/7 — the fix is boring** (236 characters)
One estimate at completion, one owner, one cut-off. A written cause before the formula: cable pulling is running 10% below tender and the remaining 1,350m carries the same rate. Finance can price that sentence. It cannot price a number.
