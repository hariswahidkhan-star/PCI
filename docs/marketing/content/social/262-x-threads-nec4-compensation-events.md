# What a compensation event does to your cost report

*X / Threads thread — 6 posts, each under 280 characters and each able to stand alone. The link sits in the final post. Character counts are for production; X counts any URL as 23 characters, so the live figures run lower.*

**Post 1/6 — the hook** (221 characters)
The instruction cost £361,000 to build. The compensation event was assessed at £338,954.

The £22,046 between them does not belong to the client, and a cost report that hides which side it sits on is worse than no report.

**Post 2/6 — what it actually is** (244 characters)
A compensation event is an event the contract puts at the client's door. It is assessed as the change to defined cost plus fee: actual cost for work already done, forecast cost for the work still to come. It is a pricing mechanism, not a claim.

**Post 3/6 — the arithmetic** (238 characters)
Worked case. A pump specification changed by instruction, before any of that work had started.

Forecast defined cost £312,400.
Fee at 8.5% = £26,554.
Assessed value = £338,954.
Built out for £361,000, so £22,046 sits with the contractor.

**Post 4/6 — budget, not variance** (221 characters)
The consequence people get wrong: an assessed compensation event changes the prices, so it moves the budget. Book it against the original budget line and you report an overrun that is really a record of a client decision.

**Post 5/6 — it moves progress too** (222 characters)
BAC £12.400m becomes £12.739m. Leave earned value at £6.90m and percent complete falls from 6.90 ÷ 12.400 = 55.6% to 6.90 ÷ 12.739 = 54.2%. Re-base the earned value in the same month or the curve shows a dip nobody caused.

**Post 6/6 — the two timing rules** (267 characters)
Assess on the forecast known when the event was notified, and do not reopen it because the actual came in higher. From that date the forecast is the contractor's risk.
