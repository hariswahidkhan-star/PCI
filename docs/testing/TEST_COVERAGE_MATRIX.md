## Current state after PR #73

The **Existing test surface** and 37-module audit below are intentionally retained as a frozen historical baseline. They must not be read as the current state. The delivered-increments log is the change record; PR #73 plus the current remediation branch have produced:

- approximately 1,100 Python `chk(...)` assertions across the backend suites, including 955 in the principal live-HTTP integration suite;
- a `PCI.Backend.Tests` xUnit project with 210 `[Fact]`/`[Theory]` test methods, in addition to the SecureExam tests;
- five Vitest/React Testing Library files with 30 passing frontend tests;
- fourteen Playwright specs with 40 primary Chromium tests / 60 configured project executions, including the complete direct-purchase certification lifecycle, seven deterministic test-user states, three-certification catalogue/detail consistency, public application-to-admin handoffs, support/privacy, two-institution isolation, Axe scans, Firefox/WebKit smoke, and mobile smoke; and
- a gating CI E2E job (the older non-blocking entry in the historical log records the suite's introduction, not its present setting).

This is a strong automated baseline, not a production-readiness claim. Candidate purchase/examination, multi-certification isolation, public Honorary/Training Partner applications, scenario accounts, support/privacy and institution sponsorship now have browser coverage; the cross-browser/mobile matrix, risk-based frontend coverage gates, and backend coverage reporting run in CI. Remaining work includes a risk-based backend coverage threshold, Founding and Honorary board-decision browser journeys, broader admin decision UI/component and visual coverage, SAST/container scanning, provider contracts, performance/resilience, populated-MySQL upgrade tests, restore/DR exercises, Render staging validation and approved external-provider sandboxes.

## Existing test surface (baseline)

- **Backend (strong, API/integration layer):** ~680 live-HTTP assertions across `backend/tests/` — `integration_test.py` (567 `chk`), `founding_test.py` (46), `honorary_test.py` (19), `honorary_application_test.py` (48), `sweep_500_test.py` (every `/api/*` route × anon/student/owner), logic suites (`lifecycle/release/casework/settings/publication/storage`), `storage_s3_test.py` (moto). Runs in CI on **SQLite and MySQL**.
- **.NET unit tests:** only `secureexam/PCI.SecureExam.Tests` (xUnit ×4). `PCI.Backend` has **no** xUnit unit project.
- **Frontend:** `tsc --noEmit` typecheck only — **no** Vitest/RTL component tests, **no** Playwright E2E, no axe/visual.
- **Absent layers:** component, browser-E2E, accessibility, visual, contract, k6 performance, dependency/secret/SAST scans, mutation.
- **Environment limit:** outbound egress is blocked in the build/test environment, so live external-provider (Stripe/Certuvo/exam-vendor/WhatsApp/Meta/Google), Render-deployment, real backup/restore/DR, and production-scale load tests are classified **External Provider / Operator Required** — documented, not simulated as if real.

## Cross-cutting structural findings

1. **Backend business logic is validated only at the HTTP/integration layer.** Pure functions (fee/discount math, exam eligibility, attempt limits, certificate rules, reminder stop-conditions, login lockout, TOTP replay) have no fast unit tests. Recommendation: add a `PCI.Backend.Tests` xUnit project for the pure/decision logic while keeping the Python suites as the integration/E2E layer.
2. **The entire React frontend is untested** beyond `tsc`. No component tests for forms/student/admin pages; no browser E2E; no accessibility. Recommendation: introduce Vitest + React Testing Library (unit/component) and Playwright (critical-journey E2E + axe) — new frameworks, additive, wired into the existing `frontend` CI job.
3. **Client-side auth guards are UX-only** (real authorization is server-enforced and well-tested); the per-section admin 403 gate is spot-checked on ~4 of ~50 sections — a cheap, high-value increment is to parametrize the existing limited-admin token across all admin section endpoints.
4. **Provider/Render/DR/perf** cannot be exercised here (egress blocked); they need staging + operator execution and are tracked as such rather than marked done.
